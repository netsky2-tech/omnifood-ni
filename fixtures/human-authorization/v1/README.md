# Human authorization conformance vectors (v1)

Shared cross-runtime vectors for the offline human authorization credential
contract. Dart and TypeScript tests consume the same file so a divergence in
either canonicalizer fails both suites.

## Contract

`canonical-vectors.json` pins three facts per canonical vector: the input JSON
text, the exact expected canonical UTF-8 text, and the lowercase `sha256:`
digest over those canonical bytes.

Because the file is authored rather than generated by the implementation under
test, it can catch a canonicalizer that drifts. Digests are computed with an
independent SHA-256 implementation over the authored canonical bytes.

## Deliberate non-normalization

`C04` and `C05` carry the same visible text in NFC and NFD form. They MUST keep
distinct canonical bytes and distinct digests: OHAC-C14N-1 forbids Unicode
normalization, so a canonicalizer that normalizes would break these vectors.

This differs from the DSI-6 `CN-AUTH-V1` contract, which normalizes to NFC.

## Vector groups

- `canonicalVectors` — inputs that must canonicalize to the stated bytes, digest
  included.
- `rejectionVectors` — inputs that must fail with the stated stable OHAC error
  code. `rawHex` carries byte sequences that are not valid UTF-8 text.

## Adding vectors

Add at least one vector for every rule that changes canonical bytes or rejection
behavior. Never regenerate a digest with the implementation under test.
