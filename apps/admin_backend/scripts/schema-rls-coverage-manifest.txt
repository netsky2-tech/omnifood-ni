# Schema RLS coverage manifest (issue #493, task T1; command ratchet added by
# issue #512 T3 slice 10).
#
# The authoritative classification ratchet for every migration-built public
# base table. It is evaluated by src/core/database/tenant-rls-coverage.ts (the
# single classification source) through scripts/verify-schema-build.sh in both
# scenarios, and by the migration-built DB spec
# (tenant-rls-coverage.db.spec.ts) through the same module.
#
# Format (one entry per table, table names only):
#   <table_name>|<classification>
#
#   direct:<SET>  — table carries tenant_id, ENABLE RLS, FORCE RLS, and a set
#                   of per-command policies that covers EXACTLY the declared
#                   command set <SET>: every declared command has at least one
#                   policy, and no policy command may exist outside the set.
#                   <SET> is one or more of the letters S (SELECT), I
#                   (INSERT), U (UPDATE), D (DELETE), for example direct:SIUD.
#                   A FOR ALL policy covers all four commands and therefore
#                   only satisfies a declared set of direct:SIUD (defensive:
#                   after slice 10 no direct table should carry one).
#   direct        — LEGACY bare spelling, kept only so the in-code fixture
#                   manifests of the DB specs keep parsing. It carries NO
#                   per-command ratchet; the production manifest must not use
#                   it and the verifier fails the run if any bare direct entry
#                   appears here.
#   parent-owned  — no tenant_id column; isolation flows through a foreign
#                   key to a tenant-bearing parent. Policy work for this class
#                   landed in issue #512 T3 slice 9. No command set: the class
#                   contract is the absence of a tenant_id column.
#   global        — reviewed platform / pre-tenant / infrastructure exception.
#                   A tenant-bearing global entry fails the gate. No command
#                   set.
#   debt          — explicit temporary tenant isolation debt. A debt entry
#                   that becomes fully tenant-protected is STALE and fails the
#                   gate until it is promoted to direct (ratchet tightens).
#                   No command set.
#
# The three declared command sets, and why each group is declared as it is:
#
#   direct:SIUD (46) — ordinary business tables whose lifecycle reads, inserts,
#                   updates AND deletes rows; their write paths mutate and
#                   remove state as part of normal operation.
#   direct:SI    (10) — append-only ledgers (sync credential events, human-auth
#                   epochs/snapshots/recovery events/terminal ack history/
#                   verification events, remediation receipts, topology
#                   revisions, kardex_correction and sys_parametros_config
#                   after slice 10 split their FOR ALL policies): rows are
#                   written once and never mutated, and the immutability
#                   triggers plus the missing UPDATE/DELETE policies both
#                   enforce that.
#   direct:SIU   (6)  — queue/state tables that mutate rows in place but never
#                   delete them (recovery tokens, rollout cohorts, tenant
#                   publication state, terminal ack floor, inventory_sync_outbox,
#                   kardex_recalculate_queue after slice 10 split its FOR ALL
#                   policy): workers claim and advance rows, nothing prunes
#                   them by policy.
#
# Every public base table absent from this list is unclassified and FAILS.
# Unknown classifications, malformed lines, unknown command letters, empty or
# duplicated command sets, and duplicate entries also fail: the manifest is
# judged fail-closed, never silently filtered.
