# Schema RLS coverage manifest (issue #493, task T1).
#
# The authoritative classification ratchet for every migration-built public
# base table. It is evaluated by src/core/database/tenant-rls-coverage.ts (the
# single classification source) through scripts/verify-schema-build.sh in both
# scenarios, and by the migration-built DB spec
# (tenant-rls-coverage.db.spec.ts) through the same module.
#
# Format (one entry per table, table names only):
#   <table_name>|<classification>
#
#   direct        — table carries tenant_id, ENABLE RLS, FORCE RLS, and at
#                   least one policy. Any of those missing fails the gate.
#   parent-owned  — no tenant_id column; isolation flows through a foreign
#                   key to a tenant-bearing parent. Policy work for this class
#                   lands in issue #493 T3.
#   global        — reviewed platform / pre-tenant / infrastructure exception.
#                   A tenant-bearing global entry fails the gate.
#   debt          — explicit temporary tenant isolation debt. A debt entry
#                   that becomes fully tenant-protected is STALE and fails the
#                   gate until it is promoted to direct (ratchet tightens).
#
# Every public base table absent from this list is unclassified and FAILS.
# Unknown classifications, malformed lines, and duplicate entries also fail:
# the manifest is judged fail-closed, never silently filtered.
