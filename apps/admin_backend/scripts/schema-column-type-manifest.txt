# Entity-declared column types that diverge from the schema built by the
# migrations (issue #405). The schema build check (scripts/
# verify-schema-build.sh) reads this file as a ratchet: it fails when a
# divergence is MISSING from this list (unlisted, new drift), and it fails
# when a line here no longer matches a real divergence (a stale entry, which
# means a column was fixed or dropped without deleting its line).
#
# Direction: downward only. Entries are removed as each converging unit
# lands; the file ends empty. Additions require a separately approved
# baseline-change decision, the same rule the Admin Backend CI ratchet uses
# (openspec/changes/restore-admin-backend-ci-baseline).
#
# STATE: empty, and that is the intended destination rather than a missing
# file. It was seeded with 91 divergences when the ratchet landed in #406 and
# emptied in order: #407 (30 annotations), #412 (the change_log actor), #408
# (six enums), #410 (audit_logs.id), #409 (49 timestamps) and finally the
# five abstract Number reflections, which are declared integer because the
# schema already is and TypeORM already resolved them that way. The check
# still fails on any NEW divergence, and a stale entry still fails, so the
# ratchet is not inert now that the list is empty -- it is clamped.
#
# Format, one entry per line, blank lines and # comments ignored:
#
#   <table>.<column>|<declared>|<actual>
#
# The drift class is NOT part of the line; it is derived at report time from
# the two canonical types:
#
#   type     The declared type and the built type differ.
#   length   Same type, but one side carries a length the other omits.
#   abstract The declaration is TypeORM's reflection of a bare @Column()
#            (Number or Date); deciding the real type is a separate,
#            per-column design decision, so it is recorded, not normalized.
