# Tenant columns that are not yet uuid. The schema build check reads this file
# as a ratchet: it fails when a tenant column that is not uuid is MISSING from
# this list (new drift), and it fails when a line here no longer matches a real
# non-uuid tenant column (a stale entry, which means the list was not tightened
# after the column was fixed).
#
# Direction: downward only. Entries are removed as each Phase 2 unit of issue
# #286 lands; the file ends empty. Additions require a separately approved
# baseline-change decision, the same rule the Admin Backend CI ratchet uses
# (openspec/changes/restore-admin-backend-ci-baseline).
#
# Format, one entry per line, blank lines and # comments ignored:
#
#   column <table>.<column>   A base table column that must become uuid.
#                             Its policies depend on it, so PostgreSQL refuses
#                             the ALTER while they exist.
#   view   <view>.<column>    A view exposing a varchar tenant column. It does
#                             not get altered itself; it BLOCKS the ALTER of
#                             the base column it reads, because PostgreSQL
#                             refuses to change a type used by a view rule.
#                             The changing unit must drop and recreate it.
